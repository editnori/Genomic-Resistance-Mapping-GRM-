## The assumption that was wrong

The plan's end-to-end cause "a tree differs" reads: "the first tree that is not identical gets a cause from the table above, computed on GRM's margin before that round; later trees follow from it" (`PLAN.md`, Boosted trees, the table under "End to end"). It took for granted that once one tree differs, the later trees differ because they are fitted on the gradients that tree changed. So the kit gave a cause to the first tree that differed and read none of the later ones.

That is false for `campylobacter_jejuni__ciprofloxacin_random_fold0`, the panel with the largest difference in a probability. Five of its trees differ, each at an equal split of its own, and before each of them GRM's and XGBoost's margins on the fitting samples still agree. None of them follows from an earlier tree. The site's Methods text said that on the two panels where a tree differed "the later trees followed from it", which was therefore false for this panel.

## Added after the plan

Each item below was written after the result had been read. None decides an outcome, and none changes a row of `summary.tsv`, `differences.tsv` or `totals.json`.

1. **A cause for every end-to-end tree that differs.** `check_gbt.trees_not_identical` takes each round that both fits keep and whose two trees are not identical. It sets XGBoost's margin on the fitting samples before that round against GRM's. If they agree within 1e-5, both fits grew the round's tree from the same state, and the tree gets the cause the plan's tree-by-tree table gives it, computed on GRM's margin. If they are further apart, an earlier tree has moved the margins, and that is the cause. The tolerance is the plan's tolerance for a leaf value, and it was chosen after the review's margins had been read. `compare.py` writes the rows to `end-to-end-trees.tsv`, and `detail.json` gains, for each panel run end to end, the largest probability gap on the fitting samples.
2. **A stricter rule for the rounding cause of the trees.** `exact.tie_cause` gives "float64 rounding broke an exact tie" only where GRM's float64 gain is above that of every lower-numbered feature of the tie and not below that of any higher one. Before, the kit asked only that GRM's float64 gain and that of the lowest tied feature differ. The 512 rows with that cause kept it.
3. **The pyscm-ml build in `environment.tsv`.** The kit builds pyscm-ml's wheel into the environment and records the environment's pip, the wheel's sha256 and the compiler named in its extension module.

`run.sh` ran again with these changes on 15 November 2026. `rerun.json` is that run's record, and the result's README says which files it wrote and which came out the same.
